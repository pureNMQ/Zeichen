# 文档模块的层级与版本边界

**Status: accepted**

04 票将文档空间拆为相互隔离的 Wiki、词典、API 定义模块：Wiki 使用“文档即节点”的父子树，词典与 API 使用各自的持久化目录承载条目。模块之间不共享父子关系或目录归属，只能通过 `mentions` 引用关联；这保留了三类内容的领域语义，又提供了可扩展的文件管理体验。

## Considered Options

- 将三类文档混入一棵跨类型树：拒绝。会使词条、接口定义与 Wiki 目录页的含义混淆。
- 让词典/API 条目直接充当目录：拒绝。目录不是可版本化、可引用的文档。
- 将组织位置纳入版本快照：拒绝。回滚正文不应撤销用户后来完成的树和目录整理。
- 拖放同时重排顺序：拒绝。拖放只改变父级/目录归属；列表采用目录优先、标题自然顺序，避免 position 与并发重排。

## Consequences

- 删除 Wiki 子树或目录子树、以及恢复时，均递归处理整棵树；恢复必须原子化，若名称或 API endpoint 冲突则整体失败。删除不受引用阻塞，`mentions` 保留并将目标显示为已删除，恢复目标后自动有效。
- 文档版本包含标题、Markdown 正文和 API metadata，但不包含父 Wiki、目录归属或目录名称；这些组织变更以活动日志记录。
- Web 与 MCP 共享同一层级、目录、移动、删除与恢复规则。二级导航按父节点懒加载，并支持把当前文档的祖先路径展开。
