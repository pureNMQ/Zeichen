# Zeichen Deploy Upgrade

在已授权的生产升级中，对照关联需求和验收条件核对候选、备份和运行结果。生产验证遵守仓库 AGENTS.md 的专用测试账号规则。

## 选择发布流程

- 首次从 v1 迁移时，按仓库 `deploy/README.md` 的「v2 首次切换」操作。关闭业务写入和旧清理进程，从同一时间点的库与文件备份准备独立目标。核对 DOC-44 对应的演练证据和最终候选的验收清单。
- 已激活 v2 的实例按「v2 日常发布」操作。用 `deploy.ps1 -CheckOnly` 验证同一提交，按授权发布。发布器检查活动数据库版本、挂载和镜像，成功后更新维护定时器的镜像。数据库版本变更走独立迁移流程。
- 故障恢复按当前发布阶段处理。首次切换开放写入前可回到原库和原卷；开放后先保全 v2 写入。日常发布由发布器按同一 v2 库和卷恢复上一版应用。记录恢复结果。

## 验收和记录

核对运行状态、API 健康、MCP 元数据、前端产物指纹、专用测试身份的功能验收及备份位置。记录提交、候选镜像、数据库版本、时间和实际结果，隐去密钥和连接串。

在项目 Wiki 中定位部署日志。创建页使用 `wiki.create`（`project_id`、`request_id` 和包含标题、正文的 `content`）。更新已有页先用 `wiki.read` 取得当前版本，按行用 `wiki.edit` 提交 `expected_version`，并保留原有记录。写入遵循 Use Zeichen 的授权约定。
