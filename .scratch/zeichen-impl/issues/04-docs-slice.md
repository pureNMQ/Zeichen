# 04 文档工作台：模块隔离、层级管理与 Markdown 编辑闭环

Status: resolved
Type: task
Blocked by: 03, 08

## Goal

将现有“按类型卡片列表 + 对话框编辑”的文档页替换为项目级三栏文档工作台。人类在 Web 中管理 Wiki、词典和 API 定义的结构并编辑内容；Agent 经 MCP 执行同一套创建、移动、删除与恢复规则。所有决定以 [ADR 0001](../../../docs/adr/0001-document-module-hierarchy.md) 与 [文档树与目录管理调研](../../../research/document-tree-product-research.md) 为准。

## Product model and invariants

### 模块边界

- 文档空间由 **Wiki、词典、API 定义** 三个完全隔离的模块组成。一级侧边栏的“文档”是可展开父项，其唯一子入口为这三个模块；二级侧边栏始终只显示当前模块。
- 模块之间没有父子关系、目录归属或跨模块拖拽。模块之间唯一的正式关联是结构化 `mentions` 引用。
- Wiki 是“文档即节点”的树：每篇 Wiki 可空 `parent_id`，且父节点必须是同项目、未删除的 Wiki。根 Wiki 的 `parent_id` 为 `null`。
- 词典与 API 定义使用各自独立的持久化目录树。目录可嵌套；目录仅容纳本模块的条目；目录不是文档，不参与文档版本，也不能成为引用源或引用目标。

### 名称、归属与排序

- 同一父 Wiki 下的 Wiki 标题不可重复。
- 同一父目录下的目录名称不可重复；同一目录下的词条/API 显示标题不可重复。
- 词条继续保持现有“同项目标题唯一”；API 继续保持“同项目 HTTP method + path 唯一”。
- 不存在手工排序字段或拖拽排序。Wiki 同级按标题中文自然顺序；词典/API 同级目录优先、再按标题中文自然顺序。保存正文或修改 metadata 不得改变节点位置。
- 任一节点可被移到当前模块根；禁止移动到自身或后代，禁止跨模块移动。移动 Wiki 时，整棵 Wiki 子树随之移动；移动目录时，整棵目录子树随之移动。

### 删除、恢复与引用

- 删除 Wiki 或目录时递归软删除整棵子树，并在确认前显示受影响的目录/文档数量。删除引用目标不阻止操作。
- 恢复 Wiki 或目录时递归恢复整棵子树，且必须原子化：任一节点发生标题、目录名、词条名或 API method + path 冲突时，整次恢复失败，不能自动改名、不能部分恢复。
- 删除目标后保留 `Reference`；所有引用列表均把它显示为“已删除、不可打开”。恢复目标后原引用自动恢复有效，无需重新建立。
- 文档之间只使用 `mentions`。编辑器的“引用文档”操作同时插入普通 GFM 链接和建立 `mentions` 记录；例如 `[版本快照](/documents/glossary/term/<id>)`。链接 ID 在改名或移动后仍有效；链接文字不自动重写，避免一个改名产生多篇文档的新版本。

### 版本边界

- 每次显式保存均创建文档版本，最多保留最近 20 个版本；回滚复制历史快照为新版本，绝不覆盖历史。
- 文档版本必须快照 **标题、Markdown 正文、API metadata**。API metadata 包含 endpoint 与 Schema；回滚 API 文档必须同时恢复这些字段。
- Wiki 父级、目录归属、目录名称不进入文档版本。创建目录、重命名目录、移动文档/目录等组织操作只写活动日志，回滚文档版本不得撤销用户之后完成的整理。

## Web workbench

### 一级侧边栏：项目模块导航

- 保持 08 票定义的团队功能、工作区功能、当前项目切换器与权限行为。
- “文档”作为可展开父项，子项为 Wiki、词典、API 定义。父项只负责展开/收起；子项才切换模块并高亮。
- 不在文档工作台内重复放置横向 Wiki/词典/API Tab。

### 二级侧边栏：功能边界

二级侧边栏只管理**当前模块内的文件组织**，不承担内容编辑或详情阅读职责。

**必须提供：**

1. **浏览与定位**：显示当前模块的 Wiki 树或“目录 + 条目”树；初始只取模块根节点，展开 Wiki/目录时只取其直接子项与 `has_children`。从 URL 打开节点时自动加载并展开祖先路径，高亮当前节点。
2. **创建**：
   - Wiki：工具栏“新建 Wiki”创建根节点；选中 Wiki 的更多菜单可“新建子 Wiki”。
   - 词典/API：选中目录时可“新建目录”及“新建词条/API 定义”；选中条目时，上述新建操作落在其所在目录；没有选中容器时落在模块根。
3. **整理**：对当前 Wiki、目录或条目提供重命名；支持拖拽移动到合规父 Wiki/目录，或拖到当前模块根。拖拽仅表示改变归属，不出现任何排序投放提示。
4. **删除与恢复**：对当前节点发起删除并显示递归影响数；提供当前模块的“已删除”视图以发起恢复和展示原子恢复冲突。
5. **状态与权限**：viewer 可浏览、展开、打开，不能看到或触发写操作；editor/owner 可新建、重命名、拖拽移动、删除和恢复。
6. **搜索占位**：显示禁用的 `搜索文档（即将支持）` 输入框；它不接受输入、不筛选、不发送请求。必须显式设置合适的 `autoComplete`。

**明确不提供：**

- 标题、Markdown 正文、API endpoint/Schema 的编辑；编辑器工具栏、保存、版本历史、回滚、引用详情也不属于二级侧边栏。
- 源码/预览双栏、差异比较、手工排序、跨模块树、跨模块拖拽、标签、收藏或实际搜索。

### 右侧主区域：阅读与编辑

- 右侧主区域承载当前文档的详情阅读或编辑，不在 Dialog 内编辑。新建与编辑共用 `DocumentEditorPage`；创建/编辑时保留三栏工作台，保存成功后进入该文档的模块限定详情路由。
- 使用 Milkdown 作为 WYSIWYG Markdown 编辑器，保留 Markdown 字符串为后端真相。采用 GFM 子集：标题、列表、代码块、链接、表格必须在编辑、阅读与回滚后显示一致；原始 HTML 一律按普通文本处理，不注入页面。
- API 文档的 endpoint 与 Schema 表单位于右侧主区域（正文下方），从不放入二级侧边栏；保存时与标题、正文一起创建完整版本快照。
- 保存按钮只在提交期间禁用；成功后以服务器返回结果为准。页面级加载、接口和提交失败使用可关闭的 `ErrorNotification`，不渲染普通红字错误。所有新增或修改输入控件必须显式声明符合语义的 `autoComplete`。
- 发生未保存变更时，点击二级树切换文档、一级导航、返回或其他应用内离开路径，显示“保存并切换 / 放弃更改并切换 / 留在当前文档”。保存失败时停留当前文档并显示错误通知。刷新或关闭浏览器使用原生离开确认。
- 文档详情展示正向与反向 `mentions`；已删除引用目标保持可见但不可打开。版本历史不新增预览或 diff 界面。

## Routes

只实现以下模块限定路由，不兼容旧 `/documents` 与 `/documents/:id`：

```text
/documents/wiki
/documents/wiki/:id

/documents/glossary
/documents/glossary/directory/:id
/documents/glossary/term/:id

/documents/api
/documents/api/directory/:id
/documents/api/definition/:id
```

路由必须能在刷新、复制链接、浏览器前进/后退后恢复当前模块与选中节点；打开文档时还要恢复其在二级侧边栏中的祖先展开状态。

## Backend and HTTP API

1. 新增 Wiki 层级与目录持久化的迁移、模型与 service 层：
   - Wiki 文档持久化可空父 Wiki；词典/API 文档持久化可空同模块目录。
   - 目录持久化项目、模块类型、可空父目录及名称；目录类型只允许 `glossary`、`api`。
   - service 层必须集中校验同项目、模块隔离、未删除父节点、无循环、名称/endpoint 唯一性、递归删除/恢复原子性与项目角色。
2. 将 DocumentVersion 扩展为完整快照（标题、正文、API metadata），更新创建、更新、列版本与回滚 API，兼容最近 20 版裁剪规则。
3. 提供模块树 HTTP 查询：按父节点分页返回直接子项、稳定排序、`has_children`；提供节点祖先路径查询；提供当前模块已删除视图。
4. 提供 Wiki 父级与词典/API 目录的创建、重命名、移动、递归软删除、递归恢复端点；目录同样有创建、重命名、移动、删除和恢复端点。
5. `mentions` 必须继续通过共享多态引用 service 维护。删除不级联删引用；引用查询能在不解析/注入 Markdown 的前提下返回已删除目标状态。

## MCP parity

在既有 `docs.wiki.*`、`docs.glossary.*`、`docs.api.*` 名称空间中补齐与 Web 等价的能力：

- 列出模块根、指定父节点的直接子项与祖先路径；返回节点类型、父级/目录、`has_children` 和删除状态。
- 创建 Wiki 时可指定父 Wiki；创建词条/API 时可指定目录；创建词典/API 目录。
- 重命名、移动、删除、恢复 Wiki/词典/API 条目及目录。
- 文档提及以 `mentions` 建立；文档创建/更新/版本/回滚仍保留现有语义，并返回完整版本快照。

HTTP 与 MCP 必须只调用共享 service 层，得到完全相同的权限、模块隔离、循环、唯一性、删除、恢复与引用语义。

## Acceptance criteria

### Data and API

- Wiki 只能置于 Wiki 根或另一未删除 Wiki 下；词典/API 条目只能置于本模块目录或模块根；所有跨模块和循环归属请求均失败。
- 同级名称、词条项目级名称、API endpoint 唯一性在新建、重命名、移动、恢复中均一致生效。
- 删除 Wiki/目录递归软删除，恢复整棵子树；任一冲突会使恢复整体失败且数据不变；被删节点的 `mentions` 保留并在恢复后重新有效。
- 保存和回滚 API 文档时，标题、正文、endpoint、Schema 同步恢复；移动/目录改名不随回滚撤销。
- HTTP 与 MCP 针对创建、移动、删除、恢复、冲突、跨项目/跨模块、角色权限得到相同结果。

### Web

- 一级“文档”子项是唯一模块切换入口；当前模块高亮，二级侧边栏绝不混入其他模块节点。
- 二级侧边栏按父懒加载；深链接打开节点时其所有祖先自动展开且当前项高亮；查看/编辑正文后树的顺序和位置不变。
- Wiki、词典、API 在各自正确的根或父容器中新建；重命名、拖拽移动、拖回根、递归删除与原子恢复均可完成；不提供拖拽排序。
- viewer 没有任何管理操作，editor/owner 有完整管理操作；禁用搜索框可见但不能输入或请求。
- 编辑器是独立主区域的 Milkdown WYSIWYG；GFM 样例在编辑、详情、版本回滚三处一致，HTML 不执行；API endpoint/Schema 仅在右侧主区域。
- 未保存变更的树切换提供三选项对话框，刷新/关闭使用原生保护；失败以可关闭 `ErrorNotification` 呈现；每个输入均满足 `autoComplete` 约定。

## Tests

- 后端：层级/目录迁移、循环与跨模块拒绝、名称与 endpoint 冲突、稳定排序、递归删除恢复原子性、已删引用、完整版本快照与回滚、HTTP/MCP 一致性、权限。
- 前端：一级/二级导航、模块隔离、懒加载与祖先展开、创建/重命名/移动/删除恢复、角色控制、禁用搜索、未保存切换保护、GFM 阅读一致性、`ErrorNotification` 与 `autoComplete`。
- 手工验收：使用至少一篇嵌套 Wiki、一组多级词典目录、一组多级 API 目录、一个跨模块 `mentions`、一个删除后恢复的子树和一个会产生恢复冲突的子树，完整走通 Web 与 MCP。

## Explicitly out of scope

- Markdown 源码/预览双栏、全文搜索与索引、历史快照预览或 diff、自动保存、标签/收藏、手工排序、跨模块移动、树以外的文件附件管理。
- 兼容或重定向旧 `/documents` 与 `/documents/:id` 路由。
