# 16 普通成员无法查看团队与项目成员

Status: resolved
Type: bug
Priority: high
Blocked by: 02

## 问题

当前成员列表的查看权限与管理权限绑定：

- `GET /api/members` 仅工作区管理员可访问；
- `GET /api/projects/{project_id}/members` 仅项目 Owner 可访问；
- 前端侧栏仅向管理员显示“成员”入口，项目详情也仅向 Owner 展示项目成员列表。

因此，已登录的普通工作区成员无法查看团队成员；已加入项目的普通成员也无法查看该项目有哪些成员及其项目角色。这会阻碍提交 issue、任务协作时选择和确认相关成员。

## 期望

- 任意已认证的工作区成员可查看团队成员列表；
- 对于自己有项目访问权限的项目，普通成员可查看该项目的成员列表及其角色；
- 查看成员信息不授予管理权限：创建成员、重发设密链接、修改团队角色、增删项目成员、修改项目成员角色和 Owner 转让仍保持原有管理员/Owner 权限；
- 前端为只读访问提供团队成员入口及项目成员列表，并隐藏所有无权操作控件；
- 增加前后端回归测试，覆盖普通成员的只读查看和管理接口仍被拒绝两类行为。

## Answer

- `GET /api/members` 改为任意有效会话可读，成员行仍按当前会话正确标记 `is_self`；创建、设密链接、角色修改和移除继续要求工作区管理员。
- `GET /api/projects/{project_id}/members` 改为任意拥有项目访问权的成员可读；候选人查询、成员增删改和 Owner 转让仍继续要求项目 Owner。
- 侧边栏向普通成员显示“成员”入口；成员页与项目成员表均按权限渲染为只读，并完全隐藏新增、角色修改、设密链接、移除及 Owner 转让控件。
- 回归验证：后端 `test_members.py` + `test_projects.py` 共 28 通过；前端成员页、项目详情、侧边栏及成员路由相关 16 项通过；前端生产构建通过。
