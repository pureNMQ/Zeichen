# 15 严重缺陷:新增成员没有可用初始凭据，无法登录

Status: claimed
Type: task
Priority: critical
Blocked by: 02

## Question

当前“添加成员”只创建账号，未为该成员提供可用的初始密码或可完成的设置密码凭据。新成员因此无法完成首次登录，成员管理闭环中断。

复现:

1. 管理员在“成员管理”添加一个人类成员。
2. 使用该账号尝试首次登录。
3. 成员没有可用密码，无法进入设置密码流程或建立会话。

需要修复:

- 新增人类成员后必须拥有安全、可实际完成的首次凭据/设密路径；不得仅创建无密码账号。
- 管理员创建流程与成员首次登录流程前后端闭环，并明确失败提示。
- 不在成员列表、日志或后续响应中泄露明文密码。
- 补充后端与前端回归测试，覆盖新增成员后的首次登录/设密成功路径。

## Confirmed decision (2026-08-04)

采用一次性设密链接：

- 管理员创建成员成功后，仅当次返回并在前端展示可复制的设密链接；不展示或传递任何明文密码。
- 链接携带不可猜测的一次性凭据，必须有过期时间；使用成功或过期后失效，不能重复设密。
- 成员打开链接设置新密码后建立正常登录会话并进入系统；无效、已使用或过期链接给出明确提示。
- 管理员可安全地重新生成链接（旧链接立即失效）。

## 实现报告

- 新增 `password_setup_token` 迁移与模型：每个成员仅一条记录，数据库只保存 SHA-256 摘要、过期时间与消费时间；有效期为 24 小时。
- `POST /members` 仅在创建响应中返回设密链接；`POST /members/{id}/password-setup-link` 可重发并立即覆盖旧摘要。成员列表等常规响应不包含链接。
- `POST /auth/set-password-with-token` 原子地消费有效链接、写入密码并建立正常会话；已用、失效、过期或不匹配的链接统一拒绝。
- 已完成设密的成员不能重发设密链接，避免将该接口变成密码重置入口；旧的无凭据成员设密流程保留兼容。
- 前端创建/重发后展示一次性复制链接弹窗；`/set-password?token=…` 走令牌设密流程。
- 验证：后端核心测试 92 passed（MCP E2E 因本地缺少 `mcp` 依赖未纳入）、前端 58 passed，构建与 lint 通过（仅既有警告）。
- 修正设密链接误用 API 请求基址导致指向 `:8000` 的问题：新增可配置 `WEB_BASE_URL`（本地默认 `http://localhost:5173`），并以回归测试锁定 Web 地址与 API 地址分离。
