# 08 侧边栏导航重构:需求/任务上收 + 当前项目切换

Status: resolved
Type: task
Blocked by: 03

## Question

实现侧边栏导航重构(来自 optimization-backlog,用户已逐项确认):

- **侧边栏分两区**:团队功能(项目/成员/Agent)+ 工作区(需求/任务);需求/任务上收为顶层 `/requirements`、`/tasks`;**单入口**:需求/任务只经侧边栏进入
- **当前项目切换器**:侧边栏底部(用户设置上方),全局生效,localStorage + Context 持久化;无当前项目时默认选第一个可见项目;/projects 返回即"可见项目"(admin 全量,member 仅已加入);当前项目不可见(被删/被移出成员)时回退第一个可见项目
- **项目详情页**:保留并专注基础信息(名称/成员授权),移除需求/任务 tab;**不联动当前项目**(当前项目只被侧边栏切换器改变)
- **需求/任务详情页受当前项目约束**:仅当前项目的需求/任务可看,判权角色统一用当前项目角色(useProjectRole 上移全局 provider,详情页删除单独拉所属项目角色逻辑);约束失败 → 提示页 + "切换到该项目"按钮;无当前项目 → 列表/详情均空态引导(请先在侧边栏选择项目)
- **项目详情页成员授权 UI(增删改齐全)**:成员列表 + 添加(工作区成员/agent)+ 移除 + 改角色(owner/editor/viewer);后端补 `update_project_member_role` 端点;现有"最后一名 owner 不可移除"守卫照用
- **项目基础信息管理(用户验证补入)**:项目改名——后端 `PATCH /projects/{id}`(owner 可改、strip 后非空校验)+ 详情页名称旁编辑入口;改名后列表/切换器同步
- 测试:前端导航/切换器/约束门/空态/成员授权 + 后端改角色端点

## Answer

用户验收通过。侧边栏已分为团队功能与工作区，需求/任务改为顶层入口；当前项目切换器通过 Context 与 localStorage 全局持久化。项目详情聚焦项目资料与成员授权，并已完成项目改名、成员角色调整及相关前后端回归覆盖。

产出:导航双区 + 当前项目全局生效 + 项目详情页(信息+成员授权)可用闭环。
