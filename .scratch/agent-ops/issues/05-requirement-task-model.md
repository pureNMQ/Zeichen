# 05 需求生命周期与任务模型

Status: resolved
Type: grilling
Blocked by: 01

## Question

设计需求与任务的行为模型:
- 需求从提出到结项的状态流(草案:提出→评审→接受→实现中→验收→关闭?各状态谁允许流转?)
- 任务状态与指派:状态集、指派对象(人类成员 vs agent)、agent 认领/完成任务的流程
- 评论/讨论在需求与任务上如何工作(数据层面 01 已定:多态 comment 表,此处定行为语义)
- "agent 调度与执行"是否进本工具范围(本工具只记录任务,还是也负责把任务派发给 agent 去执行)——这是本 ticket 要裁决的边界问题

产出:需求/任务的领域模型 + 状态机 + 边界裁决。

## Answer

- 需求边界:单项目内的验收单元;不支持父子层级,拆解靠任务承接
- 需求状态机:`待办 → 实现中 → 验收中 → 已完成`,侧路 `已取消`;无评审态
  - 自动流转:首个任务开工 → 实现中;所有任务进入验收中 → 验收中
  - 验收:任何有编辑权主体(人/agent)置已完成 + 验收说明(活动流/评论)
- 任务模型:状态 `待办 → 实现中 → 验收中 → 已完成` + `已取消`(与需求同构,含任务级验收);assignee_id 可空,未指派=待认领;已指派仅被指派者或团队管理员可改状态/改派;需求置已完成时校验其任务不允许仍有验收中/实现中
- 评论即讨论,无"解决/未解决"标记
- 边界裁决:Zeichen 只记录、不调度——执行在外部 MCP 客户端发生,agent 调度划为 out of scope
